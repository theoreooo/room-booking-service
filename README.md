# Room Booking Service

Go-сервис для бронирования переговорок по спецификации из [`api.yaml`](./api.yaml).

## Как запустить

```bash
docker compose up --build
```

Сервис будет доступен на `http://localhost:8080`.

Проверка healthcheck:

```bash
curl -i http://localhost:8080/_info
```

## Авторизация

- Для обязательного сценария используется `POST /dummyLogin`.
- Поддерживаются роли `admin` и `user`.
- JWT содержит как минимум `user_id` и `role`.
- При создании брони `user_id` берётся только из токена.

## Выбранный подход к слотам

Использован подход с предгенерацией слотов на окно ближайших `N` дней:

- при создании расписания сервис сразу генерирует слоты на окно `WORKER_SLOT_GENERATION_DAYS` (по умолчанию `7`);
- фоновый worker периодически достраивает то же окно вперёд;
- слоты сохраняются в БД со стабильными UUID, поэтому бронирование по `slotId` соответствует требованиям спецификации.

Почему выбран именно этот подход:

- самый горячий эндпоинт — `GET /rooms/{roomId}/slots/list?date=...`;
- на чтение он работает как запрос по уже материализованным слотам, а не как дорогое пересчётное построение расписания на лету;
- это упрощает соблюдение целевого времени ответа для чтения.

## Производительность hot endpoint

Для эндпоинта списка доступных слотов используются:

- индекс `idx_slots_room_date` на `(room_id, start_at)`;
- partial unique index `idx_bookings_slot_active` для активных броней;
- выборка слотов только в рамках одной переговорки и одного дня;
- фильтрация занятых слотов через `LEFT JOIN bookings ... status = 'active'`.

При заданных объёмах данных такой путь чтения остаётся простым: поиск по индексу по комнате и дате плюс проверка активной брони на слот.

## Тесты

Запуск:

```bash
go test ./...
```

Покрытие:

```bash
go test ./... -coverprofile=cover.out
go tool cover -func=cover.out
```

Текущие обязательные сценарии закрыты тестами:

- интеграционный сценарий `создание переговорки -> создание расписания -> создание брони`;
- интеграционный сценарий отмены брони пользователем;
- unit-тесты для бизнес-логики и HTTP-слоя.
